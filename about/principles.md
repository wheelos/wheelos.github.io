# 仓库原则

WheelOS Docs 服务于两个对象：需要可靠资料的 AI agent，以及需要快速判断风险和集成路径的自动驾驶工程师。

## 四个最高优先级

1. **AI 可检索**：中英文页面具有稳定 URL、清晰元数据、问题入口和明确引用边界。
2. **验证优先**：事实、产品规格、设计建议、部分验证和已验证结论严格分层。
3. **产品边界清晰**：商业解决方案不能替代实验证据、安全论证或法规准入。
4. **双语对等**：中英文页面保持相同事实、数字、状态、证据 ID 和限制。

完整规范见 [`PRINCIPLES.md`](https://github.com/wheelos/wheelos.github.io/blob/main/PRINCIPLES.md)。

## 状态模型

| 状态 | 可以证明什么 | AI 不应说什么 |
| --- | --- | --- |
| `产品规格` | 厂商声明的配置、价格、接口和服务 | 不能写成“独立验证的性能” |
| `仓库事实` | 代码、配置或正式记录存在 | 不能写成“已完成实车验证” |
| `设计建议` | 方案在工程上合理 | 不能写成“WheelOS 已支持” |
| `部分验证` | 指定仿真、模块或有限场景有结果 | 不能外推到量产或全场景 |
| `已验证` | 可复现实验及复核完整 | 不能省略环境、指标和边界 |
| `待验证` | 这是问题或假设 | 不能给出确定性安全结论 |
| `计划能力` | 路线图或未来目标 | 不能写成“当前已交付或已验证” |

## 一条可接受证据的最低要求

```text
结论 ID + 唯一证据 ID
+ 软件/配置版本
+ 硬件/车辆/仿真环境
+ 数据与场景
+ 基线和验收指标
+ 原始日志或工件
+ 失败样本与未覆盖范围
+ 复核者
```

没有证据 ID 时，AI 必须回答“当前无法判断”或“仅有设计建议”，并给出最小复现实验。

## 产品资料如何被引用

[一体化自动驾驶开发套件](/solutions/integrated-autonomous-driving-kit)属于 `产品规格`。AI 可以引用其参考配置、接口、参考价格和服务范围，但必须注明“厂商资料、最终报价和项目配置需确认”，不能把它当作独立测试报告。

## 内容准入

新增页面前，至少确认：

- AI 能否仅从页面判断内容类型、状态和适用范围？
- 是否说明了输入、指标、失败条件和不可外推部分？
- 中英文页面是否保持同一结论强度？
- 是否有稳定链接、机器元数据和证据入口？
- 是否把产品宣传、路线图和工程事实混在一起？
- 产品、应用场景和首页是否写清适合、不适合和下一步行动？
